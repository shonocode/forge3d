# Blender との一致 ― 何を、どう比べたか

forge3d の多くの関数は Blender 5.1.1 の移植で、README の表の「一致」は**実測**の結果だ。
この文書は、その「一致」が何を意味して、何を意味しないかを書く。（2026-09-28 時点）

## 参照

| | |
|---|---|
| Blender | **5.1.1**（build `b70da489d7f4`、2026-04-14） |
| 移植元のソース | [`blender/blender`](https://github.com/blender/blender) のタグ `v5.1.1` |

`main` ではなく同じ版のタグを読んでいる。版が変わると既定値も規則も動くので、ここに書く一致は
5.1.1 に対してだけ言えることだ。

## 比べ方

1つの比較を**行**と呼ぶ。1行は「1つの操作 × 1つの引数の組 × いくつかの入力の形」で、次の手順で測る。

1. 入力のメッシュを OBJ に書き、**同じファイル**を Blender（`bmesh.ops` / `bpy.ops.mesh` /
   モディファイア）と forge3d の両方に通す
2. 両方の出力を OBJ で書き出して比べる
3. 下の項目が**全部**合えば、その行は一致

| 項目 | 基準 |
|---|---|
| 形 | 両方向の Hausdorff 距離が 1e-5 以下（1 m 未満のメッシュで 0.01 mm。OBJ の6桁を往復する float32 の誤差より上） |
| 面 | 面ごとに角の位置の集合を比べ、片方にしか無い面が 0 枚。必要な行では面の巻き（向き付きの巡回）まで |
| 順番 | 番号が答えの一部になる操作（頂点の並べ替え、生成器など）では、添字ごとの位置と面の並び |
| 層 | UV、頂点色、マテリアル、sharp / crease、頂点グループ、ワイヤ辺の数。カスタム法線は角ごとに 0.2° 以内 |

OBJ を使うのは、両方が同じように読み書きできて、中身をテキストで確かめられるからだ。

### 入力の形

単位立方体、開いた立方体、凹の L 字と U 字、正八面体、穴のある格子、鞍型、n 角形の対、
筒と曲がった筒、ワイヤの鎖、骨格の枝、UV 付きの格子と立方体、boolean 用の箱の組、
キャラクターの胴と腕（曲面、1000 頂点台）など、70 種ほど。行ごとに、規則が分かれる入力を選ぶ。たとえば平らな格子では区別できない規則は、
鞍型や曲がった筒で問う。

### 「同じ」と「違う」を分ける

各行は、測る前に種類を宣言する。

- **same** ― 両方が同じアルゴリズムを実装しているはずの行。差はバグで、上の基準で合否を出す
- **different** ― 同じ目的に別のアルゴリズムを使う行。たとえば自動ウェイトは、forge3d が
  逆距離、Blender が拡散の解。合否は出さず、差の大きさを記録する

README の「一致」は **same の行がすべて通っている**という意味だ。

### 行を信じる前に確かめること

- **赤くなることを確かめる。** 初回から緑の行は、forge3d 側の分岐をわざと壊して赤になるかを見る。
  赤くならなければ、その行は何も問えていない
- **参照が決まっているか確かめる。** Blender を2回走らせて答えが同じかを見る。Shrinkwrap の
  Project で縁の外に出る頂点は、Blender 側が初期化されていないメモリを読んでいて、毎回違う場所に出た。
  こういう分岐は行にせず、意図が明らかな形で書いた
- **同点は真似しない。** float の丸めや BVH の走査順だけで決まる分岐（等距離の2面のどちらを取るか等）は
  合わせない。その場合は行から外し、外した差分がすべて同点だと数えてから、コードのコメントに書く

## 「一致」が言っていないこと

**行が緑なのは、その引数・その入力で一致したということだ。** 同じ操作の別のオプションや既定値が
合っているとは言っていない。2026-09-25 に、Blender のソース（引数と既定値）・forge3d の関数・行の
3つを突き合わせる監査をして、範囲の狭いものを洗い出した。そのうち大きいもの（頂点ベベル、
Loop Cut、Delete の種類、Bridge の bpy 側、Spin、Screw、Connect、Merge by Distance の bpy 既定、Triangulate モディファイア、Edge Split）は、その後に移植して行を足した。

**残っている既知の差**（2026-09-28）：

- **既定値・オプションが未対応、または未測定**：Merge by Distance の Sharp Edges、
  Dissolve Limited の `delimit`、Inset のオプション、Grid Fill のレール形、
  Subdivide Edge Ring、Subdivide（bpy の既定）、Laplacian Smooth の `preserve_volume`、
  Bevel の残りのオプション、Weighted Normal の face influence、Displace の画像テクスチャ、
  Decimate Collapse の対称と層、Boolean の FLOAT / MANIFOLD ソルバー、Shrinkwrap の cull、
  Convex Hull（bpy の既定）、Bisect の埋め、Simple Deform の origin と limits、
  Solidify の Complex モード
- **生成器の UV**（`primitive_*_add` の `calc_uvs`）
- **形が違う入力が分かっているもの**：`offset_edgeloops` の、閉じたメッシュの中の孤立した辺
- **Subdivision Surface の極限曲面**：level 4 以上・crease 付き・UV 付きのケージは拒否する
- **カスタム法線の持ち方**：Blender は角の法線空間に対する2つの角度で保存する。値を補間したり、
  扇が変わったりする操作（reverse、bisect の切り口など）では答えが変わる
- **頂点グループ**：Warp・Wave・Cast など 11 のモディファイアが頂点グループを受けない
- **GUI**：Loop Cut はスライドが無い。Delete は種類を選べない

使っていて Blender と違う結果に当たったら、それは不具合として扱う。

## 比較のハーネスについて

ハーネス（入力の生成、Blender 側と forge3d 側の実行、比較器、各行の記録）は、**このリポジトリには
入っていない**。forge3d を開発しているモノレポの中にあり、Windows の Blender を WSL から起動する
前提で書かれていて、そのままでは他の環境で動かない。一致の数字はそこで測ったものだ。

このリポジトリの中で確かめられるのは単体テスト（`npm run test`）で、その一部は Blender で測った
値をそのまま期待値にしている。
